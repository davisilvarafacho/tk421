## 0. Contrato deste documento

### Objetivo

O TK-421 é um workstation Arch Linux manual, minimalista na base, moderno/entusiasta na experiência, altamente customizado e projetado para tratar agentes e IA como **first-class citizens**.

Este arquivo deve registrar:

- decisões arquiteturais;
- escolhas de software;
- configuração atual validada;
- caminhos e convenções importantes;
- estado das fases do projeto;
- pendências conhecidas;
- decisões históricas substituídas;
- direção futura já aceita.

### Regras para humanos e agentes

1. Não assumir que uma ideia discutida está implementada.
2. Distinguir sempre:
   - **✅ Validado/implementado**;
   - **🟡 Decidido/em andamento**;
   - **⏳ Planejado**;
   - **⚠️ Precisa ser verificado**;
   - **❌ Rejeitado/abandonado**.
3. Mudanças importantes no sistema devem atualizar este arquivo.
4. Não registrar senhas, tokens, secrets ou credenciais aqui.
5. Não mudar decisões visuais silenciosamente: identidade visual é parte central do projeto.
6. Não reintroduzir swap, GRUB ou decisões explicitamente rejeitadas sem nova decisão do usuário.
7. Preferir configurações compreensíveis, versionáveis e reproduzíveis.
8. Para dados grandes/imutáveis, separar lifecycle de dados do lifecycle do sistema sempre que fizer sentido.
9. Em caso de conflito com informação antiga, a decisão confirmada mais recente vence.

# 3. Disco e Btrfs

## ✅ Layout físico

```text
/dev/nvme0n1
├── p1  2 GiB       EFI System / FAT32
└── p2  ~952 GiB    Btrfs
```

Filesystem Btrfs principal:

```text
Device: /dev/nvme0n1p2
UUID:   602881d3-d37f-45a2-a310-3cf5a0137c11
```

## ✅ Subvolumes canônicos

```text
@            → /
@home        → /home
@snapshots   → /.snapshots
@log         → /var/log
@cache       → /var/cache
@docker      → /var/lib/docker
@ai-models   → /var/lib/ai-models
```

Subvolumes observados adicionalmente sob `@`, criados/gerenciados pelo systemd:

```text
@/var/lib/portables
@/var/lib/machines
```

Não devem ser alterados apenas para “limpar” a árvore.

## ✅ Política de montagem Btrfs

Opções adotadas:

```text
rw
noatime
compress=zstd:1
ssd
discard=async
space_cache=v2
```

Política geral:

- snapshots do sistema não devem arrastar `/home`;
- logs ficam fora dos snapshots do root;
- cache fica fora dos snapshots do root;
- Docker fica fora dos snapshots do root;
- modelos locais de IA ficam fora dos snapshots do root;
- compressão Btrfs permanece ativa como padrão consistente;
- `discard=async` é usado; não há necessidade de manter `fstrim.timer` em paralelo por padrão.

# 4. Subvolume de modelos locais de IA

## ✅ `@ai-models`

Criado em 2026-10-03.

```text
Subvolume:     @ai-models
Mountpoint:    /var/lib/ai-models
Device:        /dev/nvme0n1p2
Filesystem UUID:
               602881d3-d37f-45a2-a310-3cf5a0137c11
Subvolume UUID:
               d106e825-72c0-e644-adef-a06b02dddcf5
Subvolume ID:  264
Parent ID:     5
Top level ID:  5
Owner:         tk421:tk421
```

Entrada canônica no `/etc/fstab`:

```fstab
UUID=602881d3-d37f-45a2-a310-3cf5a0137c11 /var/lib/ai-models btrfs rw,noatime,compress=zstd:1,ssd,discard=async,space_cache=v2,subvol=@ai-models 0 0
```

Montagem validada:

```text
/var/lib/ai-models /dev/nvme0n1p2[/@ai-models] btrfs ... subvolid=264,subvol=/@ai-models
```

### Motivação

Modelos de IA são grandes, em grande parte imutáveis e não devem acompanhar snapshots do sistema. O subvolume isola esse lifecycle e evita que pesos de dezenas/centenas de GB poluam políticas de snapshot e rollback.

### Estrutura interna desejada

```text
/var/lib/ai-models/
├── llm/
├── vision/
├── embedding/
├── decision/
│   └── laya/
└── cache/
```

Observação: não criar um subvolume Btrfs por modelo sem necessidade concreta. O padrão é **um `@ai-models`** com organização interna por categoria/runtime.

### Direção para runtimes

Centralizar pesos e caches aqui sempre que o runtime permitir, evitando espalhar artefatos grandes em:

```text
~/.cache
~/.ollama
outros caches default de ferramentas de IA
```

Variáveis que podem ser usadas quando os respectivos runtimes forem adotados:

```text
HF_HOME=/var/lib/ai-models/cache/huggingface
OLLAMA_MODELS=/var/lib/ai-models/llm/ollama
```

Essas variáveis representam a convenção desejada; cada runtime deve ser configurado e validado individualmente antes de ser considerado concluído.
