# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

The Quickshell (0.3.2) desktop shell for the user's Arch + Hyprland (Lua config) workstation "TK-421". Entry point is `shell.qml`, which instantiates `SystemStats`, `Bar`, `Island` and `Lock`. Hyprland autostarts it (`quickshell -p /home/tk421/Development/quickshell/shell.qml` in `~/.config/hypr/hyprland.lua`), and `hypr/` in this repo is a symlink to `~/.config/hypr`, so edits there change the live Hyprland config.

**The running shell is the user's real desktop and hot-reloads on every file save.** Save each QML file once, in a working state. Content-identical saves do not reload.

## Commands

- Logs: `qs log -p /home/tk421/Development/quickshell/shell.qml`. To check only the latest reload, take the text after the last `Reloading configuration` line and count `WARN|ERROR`.
- IPC (all take `-p <path to shell.qml>`): `qs ipc -p <shell.qml> call <target> <function>`
  - `lock`: `lock` (real session lock), `isLocked`, `preview` (full-screen mock of the lock; password `preview`, Esc closes)
  - `island`: `toggle` (pin the card open), `tab <agenda|media>`, `currentTab`
  - `agenda`: `status`, `sync`
  - `usage`: `toggle`, `refresh`, `status` (Claude plan limits card)
  - `launcher`: `toggle`, `open`, `close`, `isOpen`. Do not name IPC functions `show`/`hide`: `qs ipc call` just prints the target listing for them.
  - `wallpaper`: `toggle`, `isOpen`, `next`, `prev`, `effect <laser|hyperspace|doors|scan>`, `apply`, `cancel`, `status`, `list` (the picker; `next`/`prev` only act while it is open). **Tests change the real desktop wallpaper**: note `awww query` first and return to that image through the model (`apply`), never leave the picker open.
  - `dropdown`: `open <power|tray|menu|net|bt|sound>`, `close`, `status`. `power`: `status`, `setDryRun`, `ask <id>`, `cancel`, `confirm`, `run <id>` (ids: `lock suspend logout reboot poweroff`). `tray`: `status`, `list`, `activate <i>`, `menu <i>`; `traymenu` (only while a tray menu is open): `rows`, `click <i>`, `back`.
  - `notifications`: `toggleCenter`, `toggleDnd`, `clear`, `status`, `inject <normal|actions|critical|low|long>` (fake notification, only while `Notifications.mock` is true).
  - `net`: `status`, `list`, `networks`, `setDryRun`, `setMock`, `setMockMode <eth|wifi|off>`, `disconnect`, `connect`. `bt`: `status`, `list`, `setDryRun`, `setMock`, `power <bool>`, `scan`. `sound`: `status`, `list`, `setMock`, `setMockMic <on|muted|missing>`, `volume <out|in> <percent>`, `mute <out|in>`, `use <out|in> <index>`.
- Agenda Python (uv project in `agenda/`): `cd agenda && uv run pytest tests -q`; one test: `uv run pytest tests/test_sync.py::test_name -q`; real feed check: `uv run sync.py --check` (prints names and counts only).
- Visual checks: `grim -g "906,4 748x424" <file>` captures only the island card. Never grab the full screen, other windows may show private content.
- Moving the cursor for hover tests: `hyprctl dispatch 'hl.dsp.cursor.move({ x = 1280, y = 14 })'`. `/dev/uinput` is writable by the user, so virtual keyboards/mice work for input tests.

**Never call `lock lock` while testing.** The only way out of the real lock is the user's password: there is no passwordless unlock, and `pam_faillock` locks the whole account for 10 minutes after 3 wrong passwords (TTY and sudo too). Reset with `faillock --user tk421 --reset`.

## Architecture

- **`services/`** are singletons registered in `services/qmldir`: `Audio` (PipeWire default sink, emits `changed`), `Media` (normalised MPRIS player, has a `mock` mode), `Agenda` (calendar events). `SystemStats` is a plain component. New singletons must be added to the `qmldir` or they will not resolve.
- **`theme/Theme.qml`** holds the palette. `Theme.imperial.*` is the official palette from `tk421/TK421.md`; the older top-level tokens are only for legacy code. Fonts: Orbitron for the clock and labels, Geist for UI, Symbols Nerd Font for icons. UI copy is English.
- **`island/`** is the Dynamic Island that replaced the bar clock. It is its own `PanelWindow` (top layer) whose input mask is only the animated card, so the rest of the window is click-through. State priority: open > volume HUD > media pill > idle. The HUD only reacts to volume; there is no brightness backend (`brightnessctl` and `ddcutil` are not installed). It aligns with the bar capsule (top 4 px, 28 px high). The open card has two tabs, AGENDA (`CalendarPane` + `AgendaPane`) and MEDIA (`MediaPane`), switched from a text row in the top-left corner; it always reopens on AGENDA. The body un-blurs while opening (`MultiEffect` only during the animation). Prototype: `prototypes/island-media-tab/index.html`.
- **`lock/`** is the lock screen: `WlSessionLock` + `PamContext` using `/etc/pam.d/hyprlock`. `LockSession` holds auth state, `LockSurface` the wallpaper and animation, `LockCard` the three-pane card. `SUPER+L` and the `hypridle` `lock_cmd` call `lock lock`, falling back to `hyprlock`.
- **`launcher/`** is the app launcher that replaced Hyprlauncher: a fullscreen overlay `PanelWindow` (exclusive keyboard focus while open) with the card at 24% height. Apps come from `DesktopEntries` and launch with `entry.execute()`. `Fuzzy.js` does the ranking and escapes names before they reach `StyledText`. Palette is graphite and steel only, no hue (decided with the user, see `prototypes/launcher/index.html`; `v1`–`v4` there are rejected iterations). `SUPER+Space` calls `launcher toggle`, falling back to `hyprlauncher`. Hover only selects on real pointer movement: a parked cursor must not steal the keyboard selection.
- **`wallpaper/`** is the wallpaper picker (spec `docs/superpowers/specs/2026-10-14-wallpaper-picker-design.md`, plan `docs/superpowers/plans/2026-10-14-wallpaper-picker.md`, prototype `prototypes/wallpaper/index.html`). `SUPER+ALT+B` (bind in `hypr/hyprland.lua`) calls `wallpaper toggle`: a blast door opens in the middle of the screen, ←/→ (or the mouse wheel over the bay) change the wallpaper live, ↑/↓ (or click / wheel on the single effect button in the lintel) pick the transition (SUPERLASER default, HYPERSPACE, BLAST DOORS, TACTICAL SCAN; it applies to the next change and never touches the desktop), Enter keeps it, Esc restores the original. **`awww` stays the real wallpaper.** `services/Wallpaper.qml` is the model (folder `~/Pictures/Wallpapers`, `applied`/`shown`, effect, IPC, persistence in git-ignored `wallpaper/state.json`); `WallpaperStage` is a Bottom-layer, click-through window (above the awww background, below every window) that draws the transition and hides right after `awww img --transition-type none` has taken the new image; `WallpaperPicker` is the door (Overlay layer, exclusive keyboard); `effects/*.qml` share one interface (`fromSource`, `toSource`, `progress`) and are ported from the prototype's `render(p)`. `wallpaper/logic.js` is pure and tested (`tests/qml/tst_wallpaperlogic.qml`). `wallpaper/restore.sh` runs from the "TK421 SESSION STARTUP" block of `hypr/hyprland.lua` at login and repaints the saved wallpaper (`tests/wallpaper-restore.sh`). The applied wallpaper always appears in the bay, even when it lives outside the folder. `Theme.imperial.accent` is blue, so the picker keeps its own steel tokens. Inline `component X:` types cannot see ids of the enclosing file: pass what they need as properties. **`WheelHandler` never fires in a Quickshell window on this setup; read the mouse wheel with `MouseArea.onWheel`** (`acceptedButtons: Qt.NoButton` to take only the wheel). To test the wheel, create a virtual mouse on `/dev/uinput` (REL_WHEEL plus REL_WHEEL_HI_RES, a small REL_X nudge first so the surface gets a pointer-enter) after moving the cursor with `hyprctl dispatch cursor.move`, and restore the cursor afterwards.
- **`usage/`** is the Claude plan-limits widget (5 h session, 7 d week): `usage/fetch.py` (stdlib only) reads the Claude Code OAuth token from `~/.claude/.credentials.json`, calls the undocumented `api.anthropic.com/api/oauth/usage` endpoint and prints one JSON line (`ok` or `error` code). `services/ClaudeUsage.qml` runs it every 5 min (1 min while offline), `bar/UsageChip.qml` is the toolbar item, `usage/UsageCard.qml` the dropdown. Never print or store the token, and never refresh it from here: the refresh token rotates and could sign Claude Code out (an expired token shows OFFLINE until Claude Code renews it). The endpoint is not public API and may change. Tests: `python3 -I -m unittest discover -s usage -q` (from the repo root); `usage/logic.js` is plain JS.
- **`notifications/` + `services/Notifications.qml`** (spec `docs/superpowers/specs/2026-10-12-notifications-design.md`, prototype `prototypes/notifications/index.html`): own notification server, **the real daemon since 2026-10-17** (`Notifications.mock` is `false`, `swaync` is out of the Hyprland autostart, `SUPER+N` calls `notifications toggleCenter`). `inject` only works while `mock` is true; test with real `notify-send` and clean up with `notifications clear`. Popups are an island state (`island/NotificationToast.qml`, priority open > notify > hud > media > idle; hovering a popup expands it and pauses its 5 s countdown, it does not open the card). History lives in a **translucent drawer** from the right edge (`notifications/NotificationCenter.qml`, namespace `tk421-notifications`, alpha 0.72 plus the Hyprland blur rule, `NotificationItem` rows, `components/AppTile.qml` icons). The copy is Imperial in the labels only (COMMS LOG, PURGE, COMMS SILENCED, NO TRANSMISSIONS, TRANSMISSION / PRIORITY ALPHA, ROUTINE; time labels `NOW`, `4M`, `2H`), titles and bodies are the apps' own. DND shows a `COMMS` HUD pill. `notifications/logic.js` is pure and tested (`tests/qml/tst_logic.qml`, run with `/usr/lib/qt6/bin/qmltestrunner -input tests/qml/tst_logic.qml`). The drawer also yields to `Dropdown.held`, so `SUPER+S` can capture it: `hypr/tk421-screenshot.sh` holds the focus grabs of the dropdowns and the drawer while `slurp` runs.
- **`clipboard/`** is the clipboard archive that replaced `cliphist list | fuzzel` (spec `docs/superpowers/specs/2026-10-17-clipboard-archive-design.md`, prototype `prototypes/clipboard/index.html`). `SUPER+H` calls `clipboard toggle` (falls back to fuzzel). The store is still `cliphist` with its two `wl-paste --watch` user services; the shell only reads: `cliphist list` on open, `cliphist decode` for previews, copy-back and paste, `cliphist delete` for Del. `ClipboardCard.qml` is a launcher-style overlay (namespace `tk421-clipboard`, blur rule in `hypr/hyprland.lua`): 560 px, 880 px while an image record is selected (image beside the list, text under it). Enter copies back, **Ctrl+Enter also pastes** through `clipboard/paste.lua` (Lua: `wtype`, `Ctrl+Shift+V` in terminals, `Ctrl+V` elsewhere, window class from `hyprctl activewindow -j`), Del purges (only with the text cursor at the end of the query). `ClipImage.qml` decodes images to `$XDG_RUNTIME_DIR/tk421-clipboard/<id>.bin` (tmpfs, never the project dir). `clipboard/logic.js` is pure and tested (`tests/qml/tst_cliplogic.qml`). **The archive shows the user's real clipboard, which can hold passwords: never `grim` it with a real history, and never copy, paste or purge real records in a test.**
- **Lock backdrop and boot lock.** `lock lock` and `lock preview` first run `lock/capture.lua` (one `grim` per output into `$XDG_RUNTIME_DIR/tk421-lock/`, mode 700, deleted on unlock), and `LockSurface` shows that screenshot as a still image, slightly dimmed (brightness -0.25, no blur; the user chose a static photo over a live view, windows are not drawn while locked so a video behind it would freeze anyway), falling back to the wallpaper if there is none; the lock never waits more than 3 s for it. **`hypr/tk421-boot-lock.lua`** is the first item of `hyprland.start`: when greetd's `initial_session` starts Hyprland with `TK421_BOOT_LOCK=1` (`/etc/greetd/config.toml`, edited by the user with sudo; backup `config.toml.bak`) it waits for the shell, calls `lock lock`, checks `isLocked` and falls back to `hyprlock`; without that variable it does nothing. Test it only with `lua hypr/tk421-boot-lock.lua --dry-run` (never without the flag: it would really lock).
- **`resources/` + `services/Resources.qml`** is the hover panel of the CPU/RAM/GPU capsule (prototype `prototypes/resources/index.html`, three 240 px blocks). Hovering the capsule (`HoverHandler` in `bar/Bar.qml`) or the panel keeps `Resources.open` true; it closes 180 ms after the pointer leaves both. `Resources` reads load, per-thread load, memory, GPU busy and VRAM every second, always (60-sample history for the graphs), and `resources/sample.lua` (Lua, ~0.5 s) every 2 s only while open: CPU temperature and clock, GPU temperature, power, fan, and the busiest processes grouped by command name (CPU as percent of one thread, memory as RSS, which double-counts shared pages). `resources/logic.js` is pure and tested (`tests/qml/tst_reslogic.qml`). GPU numbers use `card1` like `SystemStats`; the capsule's own values still come from `SystemStats`. Namespace `tk421-resources` is in the Hyprland blur rule.
- **`hypr/tk421-terminals.sh`** builds the terminal wall (htop, fastfetch, cmatrix, cava, tty-clock, shell) on workspace 10 at login, called from `hyprland.start` in `hypr/hyprland.lua`. It focuses the workspace, opens one Ghostty at a time and uses dwindle `preselect` plus `splitratio` deltas (`splitratio exact` is not accepted); it is idempotent and returns to workspace 1. When testing it, run it on a spare workspace (`tk421-terminals.sh 9`) and clean up by killing only the ghostty PIDs that own windows there (never the shared ghostty process).
- **`terminal/`** holds the Ghostty themes: `TK421-Imperial-Mono` (**official since 2026-10-14**: graphite greys only, no hue) and `TK421-Imperial-Mono-Red` (the same greys plus Imperial red for errors), each with a fish `.theme` twin. `terminal/set-theme.sh <Mono|Mono-Red>` points `~/.config/ghostty/config.ghostty` at the file by absolute path and saves the fish colours (fish 4: `theme save`, universal variables; `choose` is session-only). Tide and fastfetch use named ANSI colours, so they follow the palette untouched. Pre-change backups: `~/.config/ghostty/config.ghostty.bak`, `~/.config/fish/fish_variables.bak`. `terminal/try-palette.sh [--shell|--fastfetch] [theme file]` opens a separate Ghostty process (`--gtk-single-instance=false`, class `com.tk421.palette`) to test a theme without touching the config. `~/.config/fastfetch/config.jsonc` is the boxed Hardware/Software layout (fastfetch preset `examples/2.jsonc`, own `damdestroyer.png` logo, no `publicip`, no colours of its own); backup `config.jsonc.bak`. The old `TK421-Imperial-Destroyer` and `Steel`/`Graphite` themes are kept for comparison.
- **`agenda/`** is the Google Calendar sync: `sync.py` fetches the secret iCal feed, normalises it and writes `agenda/cache/agenda.json` atomically; `services/Agenda.qml` watches that file and runs the script every 15 minutes through `uv run --quiet --project agenda agenda/sync.py`. Status values: `unknown | ok | stale | unconfigured | error`. Google's feed can lag by hours. Design docs: `docs/superpowers/specs/` and `plans/`.
- **`dropdown/` + `bar/` right side** (spec `docs/superpowers/specs/2026-10-12-power-and-tray-design.md`, prototype `prototypes/toolbar/index.html`): the bar's right side is a tray capsule (`bar/TrayCapsule.qml`, apps with a StatusNotifierItem) left of the toolbar capsule (`bar/Toolbar.qml`: Claude usage chip, notification bell, power button). Every dropdown opens in **one shared window**, `dropdown/DropdownHost.qml`, driven by the `Dropdown` singleton (`current` = `power | tray | menu | net | bt | sound`); `HyprlandFocusGrab` closes it on an outside click, a click on the same button right after that must not reopen it (`Dropdown.recentlyClosedByGrab`). `Power` runs the actions (`dropdown/power.js` has the commands, unit-tested) and **`Power.dryRun` was switched to `false` on 2026-10-13: the power buttons really act.** Never test a power action: the IPC `power run`/`confirm` refuse unless `dryRun` is true, `power ask`/`cancel` are safe, and no test may set `dryRun` to false (the shell hot-reloads while other sessions edit the repo, a reload resets the flag to its default). `Hud` is the brief island pill ("SUSPENDING dry run", "Alpha Opening"). `Tray` (service) partitions the tray items (`bar/trayLogic.js`, 3 visible, passive ones behind the chevron). A tray app's menu is read with `QsMenuOpener`: **one opener per submenu level**, because an opener drops the entries of the menu it leaves, including the entry that opened the next level. Name clash: a component named `Tray` collides with the `Tray` singleton, hence `TrayCapsule`. The toolbar order is usage chip, network, Bluetooth, volume, microphone, bell, power. `Net` and `Bt` read `Quickshell.Networking` / `Quickshell.Bluetooth` (only NetworkManager-managed devices count: the Docker bridges are ignored) and have a `dryRun` flag, **now `false` (released 2026-10-13): connect/disconnect/pair/adapter switch act for real**. Never exercise them against the real connection or devices in a test (cutting the Ethernet also cuts a remote session): use `Net.mock`/`Bt.mock`. Scan is read-only. `Net.mock`/`Bt.mock`/`Sound.mock` feed fake Wi-Fi, devices and microphone states for visual checks (this machine has no Wi-Fi adapter and no paired Bluetooth device). `Sound` wraps PipeWire for the bar (default output/input volume and mute, three microphone states, quick device switch); `dropdown/soundlogic.js`, `netlogic.js` and `bar/trayLogic.js` are pure and unit-tested.
- `bar/Clock.qml` and `flyouts/VolumeFlyout.qml` are superseded by the island and not instantiated.

## Conventions and gotchas

- **Prototype first:** new visual components start as HTML in `prototypes/<feature>/` and get approval before any QML. **Whenever you make or change a prototype, give the user its full absolute path in the reply** (for example `/home/tk421/Development/quickshell/prototypes/resources/index.html`), not a relative one, so they can open it directly. The visual direction (Imperial: cold, precise, sharp corners, no neon or heavy glass) is in `tk421/TK421.md`; do not change it silently.
- Inside a `WlSessionLock` surface, an `id` with the same name as a property of the child (for example `session: session`) resolves to `undefined`. Use distinct ids (`authSession`).
- Small text needs `renderType: Text.CurveRendering` to avoid coloured LCD fringes. Strings from outside (event titles, media metadata) must use `textFormat: Text.PlainText`, because invites can come from strangers.
- The secret calendar link lives only in `agenda/agenda.toml` (mode 0600, git-ignored). Never read it, print it or ask the user to paste it into a chat. Config, cache and the `.venv` all stay inside the project (git-ignored), not under `~`.
- `~/.local/bin` may be missing from PATH when Quickshell starts from the Hyprland autostart, so the agenda command prefixes it explicitly.
- Other sessions edit this repo while you work (`shell.qml`, `bar/Toolbar.qml`, `services/qmldir`, `CLAUDE.md` change under you). Patch shared files with exact-match replacements that assert their match count, never rewrite them whole.
- Real pointer tests race with the user's own mouse: a virtual click lands wherever the real cursor is. Prefer IPC hooks (`tray menu`, `traymenu click`) and `dropdown open`; if a hover is needed, move the cursor and re-read `hyprctl cursorpos` before capturing. Tray tests use a fake StatusNotifierItem (Python `dbus-next` in a scratch venv; `pgrep -f`/`pkill -f` match your own command line, use PIDs from the item's log). `Quickshell.shellPath("shell.qml")` is the real path of the config; `Qt.resolvedUrl` returns a virtual `qs:@/` path.
- Dropdown panels (`dropdown/*Panel.qml`) are loaded by a `Loader` in `DropdownHost.qml`: saving only a panel does **not** hot-reload the shell. Make a real edit to `DropdownHost.qml` (or another watched file) to trigger it, and check the reload count in the log. A dropdown also closes by itself when another window takes focus, so for `grim` first confirm `dropdown status` and capture only a region fully inside the panel (browser windows behind it can show private content).
- Qt's Wayland text-input warning (`enableSurface/disableSurface ... has focus`) is logged once per closed focus-taking layer window (launcher, dropdown). It is harmless.
- The repo currently has no commits; do not commit unless asked. `TODO.md` is the user's own backlog.
- The workspace-level `/home/tk421/Development/AGENTS.md` describes the other projects; its commit style (`feat:`, `fix:`) applies here if commits are requested.
